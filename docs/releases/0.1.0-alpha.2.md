# Permesh 0.1.0-alpha.2

Second CLI prerelease for evaluation, not stable v0.1. Download it from the
[alpha.2 release page](https://github.com/NIPE-Solutions/permesh/releases/tag/v0.1.0-alpha.2).
The published alpha.1 artifacts remain unchanged.

- Released source: [`aad58397e139ed755fcf983da8e9f045e7e5a556`](https://github.com/NIPE-Solutions/permesh/commit/aad58397e139ed755fcf983da8e9f045e7e5a556).
- Native build, tests, packaging and same-run provenance: [Attested native candidates run 34273757910](https://github.com/NIPE-Solutions/permesh/actions/runs/34273757910).
- Distributed subjects: five native archives, five target-bound dependency

  without rebuilding or recompression. The signed subjects pin the repository,
  signing workflow, source/signer commit, `refs/heads/main`, SLSA v1 predicate and

This evidence qualifies those exact artifacts. It does not retroactively attest
alpha.1, qualify a newer checkout, supply platform code signatures or prove live
provider/desktop behavior.

## Changes since alpha.1

- Explicit [browser OAuth login](../browser-auth.md) for approved external
  providers: `auth login INSTANCE --browser`, with `--no-open` for manual browser
  opening. The host owns PKCE S256, random state, a bounded localhost callback,
  token exchange and one same-instance refresh-token keychain write. The provider
  declares the flow; it receives no authorization code or browser token response.
- Optional draft-4 authentication descriptions alongside unchanged draft-2
  discovery and draft-3 setup. Existing providers remain usable without browser
  support. OAuth client IDs and required client-secret references come from the
  user's own registered application.
- Explicit [Google migration](../google-migration.md), preserving provider IDs,
  customer IDs, aliases, authoritative identity sources and credential references.
  Migration does not execute provider code, resolve credentials or approve the
  resulting workspace. The bundled Google compatibility source remains available.
- Native jobs exercise synthetic controlling-PTY behavior on all four Unix
  targets, including hidden input, EOF, echo restoration and output redaction.
- Release archives have adjacent target-bound dependency inventories and
  checksums. Inventory schema 1 binds executable and Cargo.lock SHA-256 digests to
  the target/version; it is not a CycloneDX/SPDX standards SBOM.
- The manual workflow generated and independently verified GitHub provenance for
  all 20 same-run subjects. The published bundle supports verification against
  the exact released source and signer.

Provider releases remain separate. The official catalog is authoritative for
installable versions. Google 0.1.1, Cloudflare 0.1.0 and AWS 0.1.0 remain
unpublished drafts; GitHub 0.1.0 is the only published official provider. The CLI
never installs or updates providers automatically. Browser login requires a
provider release that declares this capability, plus prior binary trust and full
workspace approval.

## Evaluation limits

- This remains an alpha with no stable compatibility guarantee. Workspace and
  output schema 1, provider setup schema 1 and wire drafts are separate contracts.
- Platform executables remain unsigned and unnotarized. Provenance attestations
  authenticate build subjects; they are not Apple notarization, Windows
  Authenticode or a reproducible-build guarantee. Checksums alone detect
  corruption, not publisher impersonation.
- Five targets passed native qualification: macOS Apple Silicon/Intel, Linux GNU
  x86_64/ARM64 and Windows x86_64. This establishes behavior on the actual runner
  images, not older OS compatibility. GNU Linux
  builds use Ubuntu 24.04 system libraries; no musl/static or older-OS claim is made.
- Browser callbacks, token responses and cancellation are covered by synthetic
  tests. Real Google consent, configured client credentials, tenant visibility,
  and live refresh-token/keychain behavior still need explicit acceptance.
- Runner credential-store and Unix PTY tests do not qualify Windows terminal
  behavior, interactive desktops or accessibility across terminal emulators.
- Dedicated live GitHub team/pagination/denied-permission/revocation fixtures and
  Google tenant coverage remain open. Mock API tests do not close these gates.
- Results describe observed access with explicit completeness and certainty,
  rather than exhaustive effective authorization. Trusted external executables
  run with the user's privileges and are not sandboxed.
- AWS profiles, shared credential files, SSO and automatic credential refresh are
  not implemented. The unpublished AWS provider uses explicit named references
  and observes IAM policy attachments, not effective-policy evaluation.
- Dependency inventory schema 1 is not a CycloneDX/SPDX standards SBOM. It does
  not inventory system libraries or separately distributed provider executables.
- No crates.io, Homebrew, Scoop, WinGet or AUR distribution and no CLI self-update.
